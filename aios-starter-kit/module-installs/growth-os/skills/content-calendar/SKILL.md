# Content Calendar

Turn the user's expertise + goals into a specific, postable content plan — real topics with hooks, not "post 3x a week about your niche."

## Gather

1. **Who + what** — the user's domain, audience, and current goal (from `context/*.md` — e.g. ICP, the thing they're selling).
2. **Channel(s) + cadence** — where they post and how often. Ask only if not obvious. Default: LinkedIn, 4 posts/week.
3. **Raw material** — any recent wins, lessons, customer questions, or notes to mine for topics. If they have an imports folder, draw from it.

## Output shape

A table the user can work straight from:

```
**Content plan — <channel> · <N> posts · week of <date>**

| Day | Format | Hook (the first line) | Angle / what it teaches | CTA |
|-----|--------|------------------------|--------------------------|-----|
| Mon | Story  | "<scroll-stopping first line>" | <the one idea> | <soft CTA> |
| ... |        |                        |                          |     |
```

Then 2-3 lines: which post is the "anchor" (most important), and what to repurpose it into (carousel, short video, thread).

## Craft rules

- **Every row has a real hook**, written out — not a topic label. "How we cut onboarding from 10 days to 1" beats "post about onboarding".
- **Mix formats** (story, how-to, contrarian take, proof/case, question) so the week isn't monotone.
- **Tie to the goal.** If the user is selling X, at least half the posts should warm up that audience without pitching.
- **Concrete + in their voice.** Pull from their real material; don't generate generic thought-leadership.
- Keep it to one postable week by default — offer to extend to a month.

## After drafting

Offer to draft the anchor post in full, turn one row into a carousel, or drop the plan into `outputs/` as a file.
